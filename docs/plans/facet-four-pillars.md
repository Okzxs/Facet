# Facet: четыре столпа и план развития

Дата: 23.11.2026  
База: `main` на коммите `950415d`  
Резерв наработок: локальная ветка `backup/pre-rollback-2026-11-23` (`5205666`)

---

## Зачем этот план

RX Playa — сильный проект, но это комбайн: 300 МБ, нативные модели, USB DAC, DSD, Automix, Canvas, TV/Wear, Listen Together. Догонять его по количеству фич бессмысленно.

Facet должен выигрывать не количеством, а цельностью:

> **Лёгкий кросс-сервисный плеер, который знает, где что играет, и не заставляет выбирать сервис.**

Четыре столпа:

1. Один трек — все источники.
2. Импорт без боли.
3. Волна, которая объясняет.
4. Текст, который не стыдно открыть.

Ограничения:

- APK не больше ~40 МБ.
- Холодный старт не хуже текущего.
- Никаких ONNX, C++, USB DAC, DSD, Automix.
- Каждый спринт — отдельный коммит, тесты, живой тест.
- Не мержить backup-ветку целиком; только точечные куски.

---

# 1. Один трек — все источники

## Цель

Пользователь видит один трек, а не три одинаковых результата. Facet сам решает, откуда играть, и показывает это честно.

## Доменная модель

Канонический ключ:

```text
MusicNormalizer.trackKey(artist, title)
```

Новая таблица `track_variants`:

```text
canonicalKey   TEXT
trackId        TEXT
source         TEXT
sourceUrl      TEXT
durationMs     INTEGER
artworkUrl     TEXT
confidence     REAL
lastCheckedAt  INTEGER
```

Первичный ключ: `(canonicalKey, trackId)`.

Опционально `canonical_tracks`:

```text
canonicalKey   TEXT PRIMARY KEY
title          TEXT
artist         TEXT
primaryTrackId TEXT
updatedAt      INTEGER
```

Почему отдельная таблица, а не поле в `Track`:

- очередь, лайки, история и плейлисты продолжают жить на `trackId`;
- канонический слой — это read-model;
- миграция не переписывает существующие таблицы.

Room v20 + миграция `19→20` + тест `DatabaseMigrationTest`.

## Repository

`CanonicalTrackRepository`:

- `canonicalize(tracks): List<CanonicalTrack>`
- `variants(canonicalKey): List<Track>`
- `bestForPlayback(canonicalKey): Track`
- `recordVariant(track, confidence)`
- `resolveByTrackId(trackId): CanonicalTrack?`

`TrackMerger` уже умеет группировать — используем его, а не пишем третий матчер.

## UI

Поиск:

- одинаковые треки схлопываются в одну карточку;
- бейдж источника: `SC`, `YT`, `SP`;
- если источников несколько — `×3` или набор бейджей.

Карточка трека:

- тап по бейджу открывает шторку «Где играет»:
  - источник;
  - длительность;
  - качество/доступность;
  - кнопка «Играть отсюда».

Библиотека:

- лайки, история, плейлисты показывают каноническую карточку;
- вариант источника раскрывается внутри.

Плеер:

- строка «Источник: YouTube» становится кликабельной;
- можно переключить вариант без потери позиции.

## Fallback

`PlaybackResolver` при ошибке источника:

1. пробует свою запись;
2. ищет варианты в `track_variants`;
3. играет лучший;
4. показывает «Играет YouTube вместо SoundCloud».

Молчаливой подмены быть не должно.

## Definition of done

- Один и тот же трек из SC/YT в поиске — одна карточка.
- Лайк с любой карточки попадает в один канонический трек.
- Очередь не дублирует варианты.
- Тесты: merger, DAO, resolver, миграция.

Сложность: **M**. Это фундамент для импорта и волны.

# 2. Импорт-хаб

## Цель

Один экран, через который можно затащить свою музыку и сразу увидеть, что откуда.

## Экраны

Вкладка «Импорт» в библиотеке:

### 2.1. SoundCloud-лайки

- поле профиля/ссылки;
- загрузка;
- счётчик `в профиле / доступно`;
- два списка: `SoundCloud` и `YouTube-фолбэк`;
- бейджи `SC`, `SC→YT`;
- выбор треков, «выбрать все», импорт;
- fallback-строки без чекбоксов, чтобы не путать импорт.

### 2.2. Плейлист по ссылке

- Spotify, YouTube, SoundCloud, Deezer;
- превью: название, количество, первые треки;
- импорт в `PlaylistRepository`.

### 2.3. Список текстом

- строки «артист — название»;
- поиск по источникам;
- найденные/ненайденные;
- создание плейлиста.

### 2.4. Профиль

- Spotify/SoundCloud;
- список публичных плейлистов;
- выбор нескольких.

## Правила

- Всё импортируется через канонический слой из пункта 1.
- Дубли не создаются.
- Если трек есть только в YouTube — это видно сразу.
- Импорт идёт пакетами, экран не блокируется.
- Ошибка источника не валит весь импорт.

## Что переиспользовать

Из `backup/pre-rollback-2026-11-23`:

- `ImportScreen`/`ImportViewModel`;
- `SoundCloudLikesProvider`;
- превью двух списков;
- тексты и бейджи.

Не тащить навигационный костыль с FAB: вход в импорт должен быть один.

## Definition of done

- Лайки SoundCloud импортируются с двумя списками и бейджами.
- Плейлист по ссылке импортируется с превью.
- Текстовый список создаёт плейлист.
- Повторный импорт не создаёт дублей.
- Ошибка одного источника не ломает остальные.

Сложность: **M**. Зависит от пункта 1.

# 3. Волна, которая объясняет

## Цель

Не «алгоритм сказал», а «понятно, почему этот трек и что с этим делать».

## Домен

`WaveExplanation`:

- `seedArtist`
- `seedGenre`
- `source` (лайк, история, похожий артист, новинка)
- `score`
- части score: artist / genre / novelty / popularity
- `penalties`
- `reasons: List<WaveReason>`

`WaveEngine` уже считает score — нужно сохранить разбивку, а не только итог.

## UI

В волне у трека иконка «Почему?».

Шторка:

- «Похоже на X»;
- «Ты часто слушаешь этот жанр»;
- «Новое для тебя»;
- «Похожий артист»;
- «Понижено: слишком много этого артиста».

Кнопки:

- «Больше такого» — усилить жанр/артиста;
- «Меньше такого» — ослабить;
- «Не рекомендовать артиста» — blocklist.

Debug long-press оставить для разработки, но не показывать обычному пользователю.

## Definition of done

- Любой трек волны объясним.
- Дизлайк меняет следующие 10 треков предсказуемо.
- «Больше такого» реально повышает вес, а не пишет в лог.
- Тесты на причины и веса.

Сложность: **S–M**. Движок уже есть.

# 4. Текст

## Цель

Красивый экран, который не стыдно открыть и который не требует 300 МБ.

## Этап A — визуал

- Компактная шапка: обложка, трек, артист, дизлайк/лайк/шаринг.
- Нет транспорта и слайдера.
- Back возвращает в плеер.
- Кнопка «к текущей строке» после ручного скролла.
- 34/41sp, затухание, мягкий blur.
- Морф обложки в шапку при открытии и обратно.

Это уже было в `5205666`; можно вытащить `PlayerLyrics`/`PlayerHero` из backup, но **без** кастомного морфа в мини-плеер, пока не проверен.

## Этап B — данные

- `LyricWord`, `LyricSyllable`, `sungUntilMs`, `background`, `alignment`.
- TTML и Enhanced LRC.
- Провайдеры: LyricsPlus + LRCLIB fallback.
- Word-sync подсветка.

## Этап C — удобство

- Перевод текста.
- Офсет ±2 сек.
- Выбор источника.
- Шаринг.

## Правила

- Перевод не ломает тайминги.
- Word-sync не роняет fps на MI 8.
- Если текста нет — нормальный empty state, без краша.
- GPL-атрибуция для RX-идей.

Сложность: **L**, но можно резать на A/B/C и коммитить отдельно.

# Порядок работ

| Спринт | Что | Результат |
|---|---|---|
| 1 | Канонический слой + Room v20 | трек = один, варианты внутри |
| 2 | Поиск/лайки/плеер на канонических карточках | меньше дублей, понятный источник |
| 3 | Fallback + «Где играет» | источник можно переключить |
| 4 | Импорт-хаб | лайки/плейлисты/текст в одном месте |
| 5 | Текст A + B | красивый word-sync |
| 6 | Волна объясняет | «почему» + обратная связь |
| 7 | Текст C | перевод/офсет/источник |

Почему так:

- канонический слой нужен и импорту, и волне, и fallback;
- если начать с текста — получится красивая витрина без фундамента;
- волна объясняется дешевле, чем Automix, и ощущается умнее.

---

# Критерии качества

- APK не больше ~40 МБ.
- Холодный старт не хуже текущего.
- Нет root-требований и нативных моделей.
- 398+ тестов остаются зелёными.
- Каждый спринт заканчивается живым тестом на MI 8.
- Никаких «молчаливых» подмен источника и дублей.

---

# Чего не делать

- Automix/crossfade.
- bit-perfect / USB DAC / DSD.
- Canvas-видео.
- Discord RPC.
- Listen Together.
- TV/Wear/Auto.
- 300 МБ зависимостей.

Каждая из этих вещей добавляет 10–30 МБ и вечную поддержку. Для гика это фичи, для обычного человека — шум.

---

# Риски

| Риск | Что делать |
|---|---|
| Ложные склейки треков | confidence-порог, ручное «это не тот трек» |
| Миграция Room ломает данные | тест 19→20, бэкап перед релизом |
| Провайдер текста умер | LRCLIB fallback, ошибка в UI, не краш |
| Импорт создаёт дубли | канонический слой + дедуп до записи |
| Слишком много фич сразу | вертикальные срезы, один спринт = один коммит |
